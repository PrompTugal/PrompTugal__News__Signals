# Threat model: the refresh in the reader's browser

Owner: signals.b@PrompTugal.dinis. Written 18 November 2026. To be reviewed by security@PrompTugal.dinis.

## What it is
`src/assets/signals.js` loads every list (front page, places, topics, accounts) from `https://data.promptugal.news/api/v1/social/latest.json` or `social/by-place/<place>.json` (and this site's `/assets/names.json`) when the page opens and every 10 minutes while it is visible, and redraws it (since 19 Nov 2026, at Dinis's word: "load the data in the browser"), at Dinis's word ("load data dynamically in the browser ... with the built page as the fallback").

## What it trusts
Nothing in the fetched data. It runs in the reader's browser under this site's origin.

## What could go wrong, and the mitigations
| Risk | Mitigation |
|---|---|
| DOM XSS from a fetched value | no `innerHTML`: elements made with `createElement`, text with `textContent`; links set only after the same checks as the build (https, fixed hosts and path shapes); topic and place links only for names in `names.json`, account links only for accounts the build knows |
| Third-party script or style | none; a Content-Security-Policy meta tag: `script-src 'self'`, `style-src 'self'`, `connect-src` limited to this site, data.promptugal.news, promptugal.news and the observability endpoints |
| A huge or slow answer | 15 s timeout, 2 MB cap, 500 items read, 60 shown |
| A failure leaves a broken page | on any error the built list stays as it is |
| Tracking the reader | the refresh request sends no credentials. Page counting (obs.js) is separate: each event is sealed in the browser to the drain's public key and appended to the "signals" lane, with no IP address, cookie or user-agent string; Do Not Track, Global Privacy Control and Pause stop it. The append tokens are public by design: anyone can append noise to the lane, never read it |
| Telling a third party where the reader is | none since 2026-11-19 03:20Z (Dinis, 19 Nov 2026: "remove the IP base. So we're going to keep the country still."): obs.js no longer asks ipapi.co or ipwho.is; the country comes from the browser's own time zone through the one shared table (promptugal.news assets/obs/tz-country.json, v1.1.0 from 2026-11-19 05:10Z, vendored as src/assets/obs/tz-country.json since 2026-11-19 04:51Z, checked at build against the registry's full pin obs_tz.integrity, the same version with different bytes failing the build, and a newer version in the registry shipping no table (no country) until it is upgraded, as a newer sites bar ships no bar, every entry checked, and written into obs.js so the browser makes no call for it; a null-prototype map looked up as an own key, two letters A to Z only, after events.b@'s review), and region, city and position are gone. Both hosts are out of `connect-src`, and obs.json has no `geo`. A time zone outside the table gives an empty country; a reader who sets another time zone is counted under it, which is accepted |
| The sites bar (v1.2.0, vendored) | its three files are dev@'s, post-reviewed by security@ (1.1.1 at about 01:30 UTC; 1.2.0 at 07:03 UTC, Website 055e6c1430, both 19 Nov 2026: go), copied unchanged and checked at every build against the registry's full pin for this version (bar.versions, append-only); a mismatch fails the build, and if the registry no longer lists this version the bar is left out, never shipped unchecked; its links open in the same tab; served from this host (script-src 'self'); the bar's links come from promptugal.news's registry, checked by the bar's own check() (https only, *.promptugal.news, escaped); the pop-up loads other sites' /preview.svg as an image and their /version.json as JSON, so the CSP allows https://promptugal.news and https://*.promptugal.news for images and connections only |
| A list source or filter set by someone else | `data-src` must match `^https://data\.promptugal\.news/api/v1/social/(latest|by-place/<slug>)\.json$` and `data-filter` a fixed pattern, both written by the build; compared by equality, never used in a selector |
| An old, replayed or broken file replacing a newer list | replaced only when the file has posts and a valid read time strictly newer than the built (or last loaded) one, within 2020 and tomorrow; read in bytes up to 2 MB with no redirect, no cookie and no referrer; three failures stop the 10-minute retries |
| A take-down made after the last build | the browser applies the take-downs in this site's `assets/names.json`, written at build time, so a take-down reaches the browser lists with the next build (push or scheduled rebuild); a person can push one at once |
| A shrunken file (a broken collection, or a compromised data host) | a file with under a quarter of the posts the page was built from is not shown, the same floor as the build; failures back off (10 minutes, doubling) |
